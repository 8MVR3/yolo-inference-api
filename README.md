# YOLO как HTTP-сервис

Обученная модель YOLO, завёрнутая в сервис на FastAPI: отправляете фото — получаете найденные объекты с координатами или просто их количество по классам. Так модель можно подключить к сайту, боту или учётной системе, не встраивая в них Python и нейросеть.

## Методы

- `GET /health` — проверка, что сервис жив (её же использует Docker).
- `POST /predict` — фото в поле `file`, ответ: размеры фото, количество и список объектов с классом, уверенностью и рамкой.
- `POST /count` — то же фото, ответ: сколько объектов всего и по каждому классу.

Порог уверенности задаётся параметром `conf`, например `/count?conf=0.5`. Интерактивная документация открывается на `/docs`.

Пример ответа `/count`:

```json
{"total": 23, "by_class": {"pill": 23}}
```

## Что учтено

- Фото с телефона, где поворот записан только в EXIF, перед распознаванием поворачиваются: иначе модель увидит их боком.
- Ограничение размера загрузки (по умолчанию 10 МБ, переменная `MAX_UPLOAD_MB`) и понятная ошибка 400 на файл, который не является изображением.
- Модель загружается один раз при первом запросе, а не на каждый вызов.

## Запуск

Положите веса модели в `weights/best.pt`, например из [yolo-pill-counter](https://github.com/8MVR3/yolo-pill-counter).

```
pip install -r requirements.txt
uvicorn app:app --port 8000
curl -F "file=@photo.jpg" "http://localhost:8000/count?conf=0.4"
```

На сервере: `docker compose up -d --build`. Веса монтируются в контейнер из папки `weights`, так что модель можно обновить без пересборки образа.

## Тесты

```
pip install pytest httpx
pytest
```

Тесты подменяют модель заглушкой и проверяют ответы, порог уверенности, обработку битого файла и поворот по EXIF. Для них не нужны ни веса, ни видеокарта.

## Лицензия

AGPL-3.0: сервис использует Ultralytics YOLO, который распространяется по этой лицензии.
